# Manual field overrides for the results index (outputs/dashboard/metrics.csv),
# for facts that can't be recovered from a filename alone.
#
# Format: one rule per line.
#   <glob-pattern>  <field>=<value> [<field>=<value> ...]
#
# - <glob-pattern> matches each result file's path relative to the repo root
#   (fnmatch-style: * ? [seq] all work, e.g. outputs/foo/*.json).
# - <value> "true"/"false" become booleans, digits become ints, anything
#   else stays a string. Quote values containing spaces: notes="like this".
# - Rules apply top-to-bottom; when several rules match the same file, later
#   ones win field-by-field. Put broad defaults first, specific exceptions
#   after.
# - Any field name works, not just the ones below -- an override can also
#   fix a mis-parsed map/solver/level, or add an arbitrary new column
#   (e.g. "hardware=laptop").
#
# Rebuild after editing: python3 visualisation/compute_throughput_metrics.py --dirs-file outputs/dashboard_dirs.txt
